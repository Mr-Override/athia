Contributing

A practical guide to contributing to Athia — regardless of your experience level.

You Don't Need to Be a Systems Programmer

Athia needs many kinds of contributors. While kernel development is part of the project, it is not the only part. Documentation, design, testing, architecture discussion, and community building are all essential contributions.

Documentation Contributions

Documentation is one of the most valuable ways to contribute, especially in the early stages:

  • Improve existing documentation for clarity and accuracy
  • Write new documentation for under-documented areas
  • Create diagrams and visual aids
  • Review documentation for consistency and tone

Design Contributions

Visual and UX design help shape the user experience:

  • Propose design improvements for the desktop environment
  • Contribute to the design system and design tokens
  • Create theme designs and variations
  • Review and refine design documents

Rust Contributions

When Rust code is contributed, it should follow these guidelines:

  • Follow Rust idioms and conventions
  • Write safe code — prefer safe Rust
  • Document public APIs with KDoc comments
  • Handle errors properly with Result and Option
  • Write tests for new functionality

Testing & Feedback

Testing is essential for a secure operating system:

  • Design test strategies and test plans
  • Validate implementations against design documents
  • Report bugs with clear reproduction steps
  • Review test coverage and suggest improvements

Pull Request Workflow

  1. Describe the change — explain what you are changing and why
  2. Reference related issues — link to relevant discussions
  3. Follow project conventions — match existing style and structure
  4. Keep changes focused — one pull request per coherent change
  5. Be responsive — respond to review feedback

Get Started

Read the CONTRIBUTING.md file for detailed guidelines and the Joining Athia guide for a step-by-step introduction.
