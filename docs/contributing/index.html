Contributing

Welcome! We're glad you want to contribute. Here's how to get started.

Pull Request Workflow

All contributions to Athia are made through pull requests. Follow these steps to submit your changes:

1

Fork the Repository

Fork the Athia repository on GitHub and clone your fork locally. Keep your fork updated with the upstream repository.

2

Create a Branch

Create a descriptive branch name for your changes. Keep changes focused — one feature or fix per branch.

3

Make Your Changes

Follow the project conventions and guidelines. Write clear commit messages and ensure your changes are well-tested.

4

Submit a Pull Request

Push your branch and open a pull request. Describe what you changed and why. A maintainer will review and provide feedback.

Types of Contributions

There are many ways to contribute. Find the one that fits your skills and interests.

Bug Reports

Found something broken? Open a detailed issue describing what you expected, what happened, and how to reproduce it.

Feature Requests

Have an idea? Open an issue describing the problem you want to solve and why it matters.

Documentation

Improve existing docs, fix typos, add examples, or write new documentation for underserved areas.

Design

Contribute visual designs, UX improvements, or design system updates for the desktop environment.

Architecture

Participate in architectural discussions, review ADRs, and help shape the technical direction.

Code

Write Rust code for the kernel, system services, desktop environment, or developer tools.

Documentation Guidelines

Writing Style

  • • Use clear, concise language
  • • Write in the present tense
  • • Use active voice whenever possible
  • • Define technical terms on first use
  • • Include examples where helpful

Structure

  • • Start with a brief overview
  • • Use headings to organize content logically
  • • Keep paragraphs short and focused
  • • Use lists for steps, requirements, and options
  • • Link to related documentation

Architecture Decision Records

ADRs document significant architectural decisions. Each ADR includes the context, decision, and consequences. They are stored in docs/decisions/ and follow a consistent format.

Getting Started

New to the project? Here's the best way to get oriented:

  1. Read the README — Understand what Athia is and what it aims to achieve.
  2. Review the Manifesto — Learn the principles that guide the project.
  3. Study the Architecture — Understand how the system is designed to work.
  4. Check the Roadmap — See what's planned and where help is needed.
  5. Browse Open Issues — Find something to work on. Look for good first issue labels.

Code of Conduct

By participating in this project, you agree to abide by the Code of Conduct. We expect all contributors to maintain a respectful and inclusive environment.
